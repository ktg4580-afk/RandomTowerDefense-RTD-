# 협업과 주차 보고서

## Git
1. 기능 작업 전 `git switch main && git pull` (원격 설정 이후)
2. `git switch -c feature/기능명`
3. 작게 커밋: `feat: ...`, `fix: ...`, `docs: ...`
4. GitHub PR 생성 후 상대방 리뷰, main 병합
5. 원격 GitHub 저장소 생성 및 권한 부여는 팀원이 직접 해야 함

## Notion
- 게임 규칙 / 통신 규약 / 주간 할 일 / 회의록 / 테스트 로그 / 개인 보고서
- 문제 발생 시: 현상 → 원인 추정 → 변경 → 테스트 결과

## 압축 일정
- 실제 1주차: 기존 1~2주차 범위 (접속 + 화면/주사위)
- 실제 2주차: 기존 3~4주차 범위 (몬스터 + 동기화/엘리트)
- 실제 3주차: 기존 5~6주차 범위 (채팅 + 통합 테스트)
- 이후 검증·수정·보고서·발표 준비

매주 보고서는 그 주에 **실제로** 실험/분석/수정한 내용을 중심으로 작성하고, 미리 구현한 부분의 구현 시점은 별도로 밝혀야 합니다. 매주 실제 프로젝트 상태를 압축해 제출합니다.
