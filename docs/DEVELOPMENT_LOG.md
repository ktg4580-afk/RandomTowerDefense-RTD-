# 김태규 담당 서버 개발 기록 (주차 보고서 자료)

## 방 기반 대기실 — `feature/room-lobby`

- **배경:** 기존 서버는 접속 즉시 두 사람을 하나의 대기실에 등록하고 READY가 모이면 자동 시작했음. 기획 변경으로 다중 방 목록과 방장 시작 권한이 필요해짐.
- **구현:** 사용자 등록과 방 입장 분리, GameRoom 모델, 방 생성/조회/입장/퇴장, 준비 상태 저장 및 브로드캐스트, 방장 START_REQUEST 검증, 같은 방에만 채팅 전달, 방장 위임 및 퇴장 처리.
- **알고리즘:** 클라이언트 명령 → ClientHandler에서 파싱 → GameServer에서 잠금(lock) 아래 등록·방 상태 검사 → 상태 변경 → ROOM_STATE를 방원에 브로드캐스트.
- **테스트:** `tests/integration/test_room.py`로 실 TCP 연결 4개를 열어 독립 방 2개, 정원 초과, 방장 아닌 자의 게임 시작 요청, READY 미완료 시작 거절, 정상 시작, 중간 퇴장/중단 및 채팅 전달을 검증.
- **한계:** 실제 게임 필드/주사위/몬스터 로직은 없고, 기존 Swing 임시 테스트 UI는 새 명령을 입력하는 화면이 없음. 방 목록은 요청 시 응답(자동 갱신 아님). 실 네트워크 지연·고부하 테스트는 미진행.
- **향후:** 공통 게임 상태 DTO 및 주사위 소환 요청 검증 규칙 협의 후 서버 기능 추가.

> 주간 보고서는 실제 수행 날짜 및 추가로 직접 진행한 테스트를 구분하여 작성할 것.

## 주사위 소환·합성·강화 서버 기능 — `feature/dice-server`

- **담당 범위:** 기존 방 관리 시스템에 서버 전용 `DiceGame` 모델 추가. 클라이언트/UI 파일 미변경.
- **동작:** `/START_REQUEST` 승인 시 플레이어마다 15칸·100SP 초기화. 서버가 `/SUMMON`, `/MERGE`, `/UPGRADE`를 검증하고 성공 시 `/DICE_STATE` 2개를 방원에게 송신.
- **검증:** 실제 TCP 테스트로 초기 상태, 소환 비용 증가, 강화 비용 차감, 잘못된 합성 좌표, 빈칸, 게임 미시작 및 중단 후 요청 거절, 두 플레이어 상태 분리 확인. 고정 난수 기반 Java 단위 테스트로 정상 합성 검증.
- **한계:** 몬스터 처치 및 SP 보상 미구현. 데미지/전투 반영 전이며 수치와 패킷은 팀 협의 시 변경 가능. UI와의 실제 통합은 아직 하지 않음.
- **테스트 환경:** OpenJDK 21 (실행 환경). 팀 합의 JDK 25 Windows에서 재검증 필요.
- **주간 보고서:** 실제 작업일과 수행한 테스트를 구분하여 정리할 것.
